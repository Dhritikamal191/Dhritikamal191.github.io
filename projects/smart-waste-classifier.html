01 · Overview

Project Overview

The Smart Waste Classifier explores how computer vision can support waste identification by predicting the category of an uploaded image.

🎯

Problem Statement

Identifying waste categories manually can be time-consuming and inconsistent. An image-based classification system can help users identify common waste types and provide a starting point for waste sorting workflows.

💡

Project Objective

Develop a deep-learning model that accepts an image, predicts one of the supported waste categories, returns confidence scores, and makes its predictions accessible through an application and API.

🧠

Technical Approach

The project uses transfer learning with an EfficientNet-based image classifier, a structured dataset split, model fine-tuning, evaluation, and a prediction service.

🌍

Practical Relevance

Potential applications include educational demonstrations, waste-awareness tools, and assisted sorting interfaces. Real-world waste handling still requires human verification and appropriate disposal guidelines.

02 · Dataset

Data Collection & Preparation

The project uses a garbage-classification image dataset. Images are organized by class, checked for duplicates, and separated into training, validation, and test sets.

Total Images 15,515

Data quality: The project audit identified 70 groups of duplicate images. Splits were prepared to avoid duplicate groups crossing training, validation, and test sets. The dataset is imbalanced, with clothes representing a substantially larger class than several glass categories.
03 · Model Development

Deep Learning Architecture

Transfer learning provides a practical starting point for image classification by reusing visual features learned by a pretrained convolutional neural network.

EfficientNet-Based Classifier

The model uses EfficientNet as its image feature extractor, followed by a classification head configured for the 12 waste categories. The project trains an initial model and then fine-tunes selected backbone layers to adapt the learned representations to the waste classification task.

Framework: TensorFlow / Keras
Architecture: EfficientNet-based transfer learning
Training strategy: Initial training + fine-tuning
Class imbalance: Class weights used during training

Model Development Workflow

01

Image Preprocessing

Load images from class-specific directories, apply the preprocessing expected by the model, and prepare data for batch training.

02

Initial Training

Train the classification head and establish a baseline model using the training and validation datasets.

03

Fine-Tuning

Fine-tune selected EfficientNet layers with a low learning rate to adapt pretrained features to the target dataset.

04

Evaluation

Evaluate the trained model on held-out test data and inspect classification performance, class-level errors, and confidence scores.

04 · System Architecture

From Image to Prediction

The application separates the user interface from the model-serving API, making inference accessible through an HTTP endpoint.

🖼️ Image Upload

User selects an image for classification.

⚙️ FastAPI

Receives the image and runs inference.

🧠 TensorFlow Model

Predicts the class and confidence scores.

📊 Results

Returns predictions for the interface.

🖥️

Streamlit Frontend

Provides the interactive image-upload experience and displays the predicted waste category, confidence, and alternative predictions returned by the API.

🔌

FastAPI Backend

Exposes a health endpoint and a prediction endpoint so the frontend can check model availability and submit images for inference.

05 · Deployment

Application Integration

The trained model is accessed through a backend API, while the frontend handles image selection and presents the prediction response.

❤️

Health Check

The frontend can check whether the API is responding and whether the model has loaded before enabling classification.

GET Endpoint
/health

Checks API and model readiness.

🔍

Image Prediction

The frontend sends an image as multipart form data. The backend returns the predicted category, confidence score, and top alternative predictions.

POST Endpoint
/predict

Accepts an image and returns prediction data.

Deployment note: The frontend must use the deployed backend URL through its environment configuration or Streamlit secrets. 07 · Conclusion

Limitations & Future Work

⚠️

Current Limitations

  • Predictions depend on image quality, lighting, background, and object visibility.
  • Dataset categories may not represent every real-world waste item or local recycling rule.
  • Confidence scores are not guarantees that a prediction is correct.
  • Batteries and other hazardous waste require dedicated handling guidance beyond image classification.
🚀

Potential Improvements

  • Expand training data with diverse, real-world images.
  • Improve minority-class performance using targeted data collection and augmentation.
  • Add low-confidence warnings and human-review workflows.
  • Monitor API latency, availability, and prediction errors after deployment.
  • Explore mobile-friendly inference and responsible waste-disposal guidance.
Project Summary

Turning Computer Vision into a Practical Tool

Smart Waste Classifier brings together image classification, transfer learning, model evaluation, API development, and a user-facing application. It demonstrates an end-to-end machine-learning workflow while highlighting the importance of reliable evaluation, deployment monitoring, and responsible use of model predictions.
